# V0.3 开发记录

## 阶段 1–3：审计与 P0 治疗闭环
- 读取 V0.2、接手草稿、地图与测试；修复 store 不一致和 role 类型错误；恢复 5188 服务。
- 统一时钟：任何时间推进都停在最早待处理事件；报告生成、查看与完成各有时间戳。
- 独立费用账本：收费幂等，退款关联原收费且封顶。取消退 80%、技术失败重做免费或退款、重新取样另收 100 均为教学参数。
- 住院含申请、入院、床位、评估观察、出院、后续预约；默认化疗为门诊。
- 结构化多个周期与评估；固定发热剧情必须评估与急诊处理，首剂不结束，终止／换方案也要后续复评。
- 失败修复：原有长单行源码使精确 patch 匹配失败，按函数边界重写；随后构建与 42 项逻辑测试通过。
- 当前限制：非默认方案仅为管理教学节点，不提供可执行处方；完整多患者资源共享仍待实现。
- 本阶段提交：见 Git 日志 `feat: connect V0.3 clock ledger admissions and multi-cycle journeys`。

## 阶段 4–6：病例、模式、共享资源
- 六病例从结构化数据生成不同取样候选、分期／分子证据、治疗教学日程及终点；追加一致性校验，禁止小细胞复用培美曲塞方案。
- 学习不限预算；六个顺序解锁能力目标；挑战共享预算／时钟／床位／当日加急与治疗资源。
- 多患者管理：后台患者继续更新，到期未处理事件会阻止全院时间越过。患者选择不会创建新的免费预算。
- 固定医疗剧情与种子化交通生活事件分离。交通选择真实改变账本和疲劳，不映射真实医学预后。
- 治疗前 NPC 当日血液／肾功能复查，游戏即时出报告；相同患者／周期／日重复复核不重复收费，旧报告不充当当天检查。
- 存档按主线／模式／病例隔离；挑战增加共享 campaign 档；旧 V0.1、V0.2 键不写入，可下载保留档。
- 浏览器首轮三条完整疗程通过，地图测试失败是动态导入形成重复模块单例；改用真实 canvas 位置信息断言，五条流程随后通过。
- 变更涉及 v03-campaign、v03-store、v03-engine、medical/cases、medical/validate、main、V03Panel、Hospital，以及 tests/v03、tests/playthrough。
- 提交见 Git 日志 `feat: add shared challenge campaign case validation and playable modes`。

## 2026-10-28：恢复具体病例数据

- 原因：V0.3 报告生成器把 V0.2 的具体报告替换成通用摘要，问诊也只反馈动作完成。原始资料仍在 knowledge.ts 与 investigations.ts，没有被删除。
- 修复：新增 medical/profiles.ts，恢复林晓禾原有报告与体征；其余五例在原背景上补充明确标记的虚构数值。新增 engine/clinical-record.ts 统一病历与逐订单证据权限；新增 PatientRecord.tsx，在门诊和记录面板展示结构化病历、按日期报告档案和异常期记录。
- 保存兼容：旧通用报告仅在显示时补充，不修改原存档、日期、账单或进度。治疗前复查保留当天记录，不用初诊数据冒充当前值。初诊、急性异常和治疗评估分开呈现。
- 防剧透：CT 不自动提供脑 MRI、分子结果或最终分期；同类复查也必须分别查看，不能因为读过首份血液报告就解锁所有后来报告。
- 修改文件：profiles.ts、clinical-record.ts、PatientRecord.tsx、v03-engine.ts、v03-types.ts、V03Panel.tsx、style.css，以及相应逻辑／浏览器测试、README、来源及验证文档。
- 失败与修复：最初用文字长度校验病理细节，误拒绝原版简短报告；改为验证实际组织学内容，不为通过测试填充文字。最终 54 项逻辑测试、6 条浏览器流程和生产构建通过。
- 未完成：新五例仍是教学设定，未经独立临床专家审查；未新增真实患者数据、真实疗效模型或可执行临床处方。
- 本次提交：见 Git 日志 `fix: restore detailed case records and evidence-gated reports`。

## 2026-10-30：扩展病例池与可复现抽样

- 新增梁梅（早期鳞癌）、丁岚（ALK 融合阳性）、唐叔（高龄合并症）、许安（少数转移灶）四例，病例池从 6 例扩展至 10 例；补齐独立 profile、报告、检查路径与结构校验。

## 2026-11-02：把七天任务改为日常接诊

- 用户反馈旧玩法难懂且像任务表。本次移除强制杂务、固定每日故事、行动点限制和七天后才能买家具的门槛。
- 保留 `week` 存档字段以兼容已有资金、家具、日志和患者，不重置进度；结算改为每天一次，第二天继续。
- 收入只按当天实际问诊／查看事件的不同患者计算，不奖励检查订单，不重复发放；医疗预算不变。
- 地图入口直接上班，结算页说清今天看了几人、赚了多少、离沙发还差多少。家具即时可见；护士提供待办患者定位帮助。
- 已验证两位患者交错接诊、报告阻断、买沙发、刷新后继续。67 个单测及 10 条浏览器流程通过，构建成功。无失败测试；仍有原有 Phaser 大包提示。
- 范围限制：没有新增长期 NPC 剧情、自由摆放或排班系统；10 个病例接诊完不会无限生成。没有支付系统。本次不是对留存或付费效果的验证。
