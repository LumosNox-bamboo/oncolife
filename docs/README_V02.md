# OncoLife V0.2 · 双主线与主动诊疗

中文像素医院游戏。在同一张可探索地图中，医生与患者拥有独立故事、任务和存档。没有强制切换职业：护士、其他医生和家属为 NPC。全部病例与剧情为虚构教学内容，不用于真实诊疗。

## 安装、启动与测试

Node.js 20.19+ 或 22+。

```sh
npm ci
npm run dev
# http://127.0.0.1:5188/
npm run build
npm test
npm run test:e2e
```

也可 `bash scripts/install.sh`、`bash scripts/start.sh`。E2E 默认使用 macOS Google Chrome；其他系统修改 `playwright.config.ts` 的 executablePath，或删除该配置后安装 Playwright Chromium。无在线模型、无真实患者数据、无云存档。

## 开始游戏

主菜单选择 **医生模式 / Clinical Journey** 或 **患者模式 / Patient Journey**。再次进入会继续该线存档。两条线无需互相完成，也不会共享诊断、预算、报告或任务。

- WASD／方向键移动，E 或鼠标点击附近目标。Esc 关闭面板。
- 院内导航选择地点后可“快速旅行”或“自动寻路”。方向键可取消寻路。
- “返回任务地点”直达当前主线地点，再按 E 互动。
- 门诊可集中问诊、开单、查看报告与诊断，检验／影像科仍能实际互动，不强迫每张单独跑图。
- “快进至结果 / 事件”停在下一批报告、准备完成或临床事件。＋1 天／＋1 周也会在新报告和关键事件暂停。
- 面板默认跳过已读问答；可取消勾选回看。任务提示可折叠。
- 手机使用方向按钮和交互按钮，横屏更易看清地图。
- 自动保存、手动存档、本条线 JSON 记录导出、旧档只读下载均保留。
- 首个决策前可选择学习预算不限或临床预算 9000 虚构币。大厅一次援助 3000 币。

## 医生线：先看证据，再作判断

初诊只有姓名、年龄、性别、咳嗽主诉、体温与高血压史。自行选择询问症状、危险因素、病史／家族史、体检或旧记录。没有完整诊断、分期或预填治疗答案。

检查卡提供用途、可获信息、局限、风险／负担、虚构费用与等待。可先 X 线，也可基于疑似病变直接 CT；血液、颅内评估与取样可采用不同顺序。CT 后可讨论经皮肺取样或胸膜取样：本例经皮标本不足是固定剧情，不是失败概率，也不会立刻给出诊断；可补样并重新申请病理。病理与分子检测分别解锁。

门诊的诊断工作台支持保存工作假设、修改理由、提交判断。证据不足不会因猜对答案而放行；判断错误可回看报告修订，没有虚构的严重结局惩罚。记录保留每次选择当时掌握的信息。

确认诊断并取得分子／安全证据后，讨论患者目标与意愿。可听取第二意见、进入首剂化疗准备，或在知情选择下先支持照护并约定复评。支持照护不是等效抗肿瘤治疗。化疗路径在准备至少 7 天后由医生审核、护士 NPC 完成当日核对并执行；异常事件由医生主动评估，选择院内急诊或同步会诊。复诊可先以症状／毒性／意愿为主，也可补充影像后复诊。

<details><summary>医生线一条可完成的示例路线（包含答案，建议先自行探索）</summary>

门诊询问症状 → 申请 CT → 快进 → 检验科申请血液与胸膜取样，影像科申请脑 MRI → 两次快进至报告 → 病理 → 快进 → 分子检测 → 快进。门诊提交“肺腺癌／IVA”并写明胸膜组织与影像依据 → 讨论目标和意愿 → 选择化疗准备 → 快进 7 天 → 治疗室审核首剂 → 快进第 8 天监测 → 病房评估 → 启动紧急处置（或同步会诊）→ 快进恢复复查 → 门诊完成临床复诊。可替换为先支持照护、3 天后复评；也可补充随访 CT 后结束。

</details>

## 患者线：从不确定到能够参与

从症状出现开始。大厅可决定今天预约，或先用两天安排家庭事务；可告诉姐姐寻求陪伴，也可先独自整理信息。就医后可完整描述持续时间与气促，或先简述再补充。医生 NPC 根据已经掌握的线索和标本条件开放检查，患者不能开抗肿瘤医嘱或替医生提交诊断。

等待后请医生解释已取得的结果，选择询问治疗目标或生活负担，表达是否进入治疗准备或先支持照护复评。生活安排有独立休息／社工支持与家属陪诊两条路径，费用、疲劳与感受不同；家庭沟通会解锁后续陪诊与共同求助。

化疗后的高潮是“不要独自忍耐”：主动报告异常并直接联系医护，或请已联系的家属陪同立即求助。NPC 执行安全评估与紧急流程，不由患者决定药物。恢复复查后安排生活、写下下一步，获得患者自己的日记结局。支持照护路径同样可完成生活与复评结局，不需要先走医生线。

平静感、疲劳、经济压力、生活感受均为 0–100 **叙事指标**，不是医学量表、肿瘤进展或生存预测。

## 存档与 V0.1 兼容

- V0.2 槽位：`oncolife-v2-doctor`、`oncolife-v2-patient`。
- V0.1 的 `oncolife-v1` **不覆盖、不推断迁移**。大厅有旧档只读查看与原始 JSON 下载。
- 新线无法从旧线护士阶段直接接续，因为流程和证据结构已重构。原版代码与回归测试保留，可通过 Git 的 V0.1 提交恢复旧体验。
- 刷新返回旅程菜单，选相应入口继续；人物位置回大厅，病例进度保持。
- 仅在大厅显式确认后重开当前线；另一线和旧版不变。

## 架构与扩展

| 文件 | 职责 |
|---|---|
| `src/engine/journey.ts` | V0.2 领域状态、独立主线、角色权限、问诊／检查／假设、NPC 规则、时间与关键事件、决策证据快照 |
| `src/engine/persistence.ts` | 版本化双槽位读写、保留旧档 |
| `src/engine/store.ts` | Zustand 绑定、菜单和当前面板 |
| `src/medical/investigations.ts` | 可选检查目录、成本／等待／风险／局限与病例结果、问诊数据 |
| `src/medical/knowledge.ts` | 来源、知识卡、安全门槛；按证据解锁展示 |
| `src/world/map.ts` | 原地图／碰撞、目标点、BFS 寻路 |
| `src/world/Hospital.ts` | 原创像素绘制、角色、手动／自动移动、近距离交互 |
| `src/ui/JourneyPanel.tsx` | 医生工作台、患者日记／生活面板、报告与时间线 |
| `src/main.tsx` | 双入口、像素地图、导航、时间、体验指标与 HUD |
| `src/engine/model.ts`、`clinical.ts` | 保留的 V0.1 引擎，用于历史回归；V0.2 运行时不使用 |

新增职业应新增 Journey 类型及独立初始状态、权限、目标、存档键、故事和测试，不再用角色切换伪装独立剧情。新增病例目前仍需扩展领域配置和结果数据，没有完成通用病例编辑器。新增检查必须同时填写适应证、局限、负担、来源与依赖条件；新增医学阈值需原文证据与边界测试，计算不能写在 UI 中。

## 交付范围

已完成：双线独立闭环、自主问诊／选检、逐步揭示、假设修订、不同取舍、患者生活状态与独立结局、快速旅行／寻路／任务直达、已读跳过、折叠任务、独立存档及旧档保护、中文日志与证据快照。

部分实现：医生可讨论的治疗范围仍围绕这一虚构病例；免疫治疗暂不接受是本例共同决策设定；NPC 是确定性规则和编写对话；患者检查仍需亲自参与确认；手机为基础适配；风险展示为定性负担，没有虚构风险概率。支持照护路径不模拟病情改善或抗肿瘤疗效。

未实现：多患者、其他职业主线、完整后续周期、通用病例加载器、药物真实剂量、临床专家审核、真实医保或经营系统、挑战模式、云同步。

详见 `docs/V02_AUDIT.md`、`docs/V02_TEST_RESULTS.md`、`docs/V02_DEVELOPMENT_LOG.md`、`docs/MEDICAL_SOURCES.md`。历史 V0.1 README 与浏览器基线结果在 `docs/v01/`。
