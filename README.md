# OncoLife V0.1 · 晴光医院

可行走、可切换身份、可完成一例肺癌诊疗闭环的中文像素游戏。所有患者、报告数值、费用和结局均为虚构教学内容；不用于真实诊疗，不提供药物执行剂量，不预测生存或毒性概率。

## 安装与启动

需要 Node.js 20.19+ 或 22+、npm。

```sh
npm ci
npm run dev
```

浏览器打开 http://127.0.0.1:5188 。也可执行 `bash scripts/install.sh`、`bash scripts/start.sh`。端口被占用时 Vite 会提示替代端口，不会停止其他服务。

```sh
npm run build       # TypeScript 检查及生产打包，输出 dist/
npm test            # Vitest 逻辑测试
npm run test:e2e    # Playwright 真实键盘完整流程
```

E2E 默认使用 macOS `/Applications/Google Chrome.app`。其他系统需在 `playwright.config.ts` 将 `executablePath` 改为当地 Chromium 路径或删除该项，并运行 `npx playwright install chromium`。这是测试环境限制，游戏本身可在现代桌面浏览器运行。

## 操作

- WASD / 方向键移动，走近对象后 E 或点击对象。Esc 关闭面板。
- 房间门位于中央走廊两侧，墙壁、接待台、工作站、病床有碰撞；请绕开大厅接待台。
- 大厅接待台切换肿瘤科医生、护士、患者，病例和临床时间不会重置。
- 底部方向按钮与“互动 E”供手机、平板使用；手机可横屏以看清地图。
- 临床日期仅通过“＋1 天”“＋1 周”“下一次预约”推进。院内时钟独立，不会因走路等待而推进化疗周期。
- 操作后自动保存到浏览器 localStorage，也可点击“存档”。刷新保留病例、身份、预算、报告与日志；人物位置返回大厅安全出生点。
- 环境音默认为关闭，点击可播放原创合成氛围音。

## 完成第一个病例（约 10–15 分钟）

1. 医生进入左上门诊，交谈、采集病史。
2. 回大厅切患者，门诊表达治疗偏好；切回医生。
3. 中上检验科申请血常规／肾功能和病理／分子检测；右上影像科申请分期影像。推进 2 天，检查科室查看报告。
4. 门诊确认诊断；中下办公室申请多学科会诊；回门诊讨论不同路径并共同选择培美曲塞＋顺铂。
5. 右下治疗室确认准备，推进 7 天；检验科重新申请血液，推进 1 天；治疗室医生审核当日医嘱。
6. 当天回大厅切护士，治疗室执行首周期。推进一周，时间会在发热事件自动暂停。
7. 左下病房：护士测量生命体征、上报异常。可完成倾听家庭照护支线。
8. 切医生：病房评估 → 检验科感染检查采样 → 病房开立紧急处置。不等待培养结果；这些交互不推进临床日期。
9. 切护士在病房执行已审核医嘱；切医生在检验科申请恢复复查，推进至下一预约（2 天）。
10. 影像科申请随访，推进至下一预约（2 天）；门诊完成随访与后续决策。总结在门诊和“病历 / 时间线”可查看。

病例固定于第 11 天左右首剂、第 18 天左右发热、第 22 天左右完成（取决于自行推进的日期）。不执行第二周期；严重毒性后暂停、复评减量及支持治疗。完成并不代表治愈。

学习模式无限预算、解释可见、允许尝试不同路径，错误不会终止病例。大厅可确认重新开始。临床模式从 8000 虚构游戏币开始，标准流程支出 5310；重复检查会花费额外预算，资金不足会阻止操作，大厅可领取一次 3000 教学援助。两种模式目前都显示医学解释。

## 结构

| 目录 | 职责 |
|---|---|
| `src/world/map.ts` | 房间、门、碰撞矩形、对象与空间查询 |
| `src/world/Hospital.ts` | Phaser 场景、原创像素绘制、键盘／触屏输入与行走动画 |
| `src/engine/model.ts` | 状态、角色、主线任务 |
| `src/engine/clinical.ts` | 独立临床动作、权限、费用、事件、预约与时间推进 |
| `src/engine/store.ts` | Zustand 状态、localStorage 存读与角色切换 |
| `src/medical/knowledge.ts` | 虚构病例、来源、知识卡、标签安全门槛 |
| `src/main.tsx`、`src/ui/` | HUD、交互面板、反馈、时间线与声音 |
| `tests/` | 逻辑测试、真实键盘浏览器流程 |
| `docs/` | 原始医学来源快照、提取结果、开发与验收记录、截图 |

## 新增病例

目前只有一例，**没有实现通用多病例加载器**。复制 `patient` 和病例报告配置，给状态增加病例标识；在 `clinical.ts` 为新病例明确阶段前置条件、方案、预约与异常事件；同步扩展动作类型和科室入口。将案例特有数值移入独立病例配置再扩展，不要把计算加入 React 组件。必须为新路径添加权限、不能跳步、安全边界和完整闭环测试。新增病例的时间、费用、疗效描述都要分别标注证据和虚构部分。

## 扩展知识库

在 `knowledge.ts` 的 `sources` 添加来源 ID、版本／发布日期、URL、适用地区及核验状态，再在 `cards` 中用 `source` 引用。确定性医学阈值必须有原文定位与边界测试；无法核实的规则明确标成教学占位，不做可执行用药建议。原始下载文件保留在 `docs/`，提取和审计另存。详见 `docs/MEDICAL_SOURCES.md`。

## 交付边界

**已实现：** 七个空间、行走碰撞和动画、近距离交互、三角色权限、同病例共享存档、初诊／治疗／随访、检查延迟、方案讨论、首周期、发热多步骤处置、结局反馈、支线、知识解锁、时间线、两种预算模式、移动端方向键、环境音开关。

**部分实现：** 地图为一张连续场景，按进入区域更新房间名；移动端为方向按钮而非模拟摇杆；患者行为是症状／偏好／安排体验；治疗调整结束于会诊复评，不执行第二周期；诊疗安全检查为单病例教学核对，非完整药物医嘱系统。概率模型未加入。

**未实现：** 挑战模式、多患者、真实医保／收费、完整经营经济、后续周期、通用病例加载器、云同步、真实患者数据。无 LLM 在线决策或第三方遥测。Phaser 体积导致生产包约 1.75 MB（gzip 约 425 KB），尚未做分包优化。
